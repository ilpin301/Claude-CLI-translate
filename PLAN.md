# Plan: Claude CLI Translate (cct) - Shift+drag in the terminal, click icon, see translation popup
_Round 4 - redesigned by Claude after Phase 0 measurements and a new user requirement (Shift+drag only). Earlier rounds: GLM APPROVED rounds 2 and 3 on the previous design; GLM APPROVED round 4 on this design (non-blocking follow-ups applied). Status: Phases 0-3 are implemented (see "Current status"); Phase 4 is open._

## Current status (shipped behaviour)
- **Done:** P0 spike, P1 (low-level mouse hook, Shift gating, watchdog, icon, tray), P2 (UIA worker, normalisation, Google translation, popup). Tests: `python -m pytest -q tests` -> 88 passed.
- **P3 done (written in the cloud session, logic unit-tested on Linux; the Windows-only parts - tray menu, registry autostart, mutex - still need a manual run on the Windows machine):** tray menu = Enabled, Target language (13 languages, default ru), Scope (terminals only / all apps), Font size, Start with Windows (HKCU Run, pythonw + run.pyw), Open log, Quit; single instance via `Local\ClaudeCliTranslate.SingleInstance` mutex (a second launch exits silently); first-run balloon once (`first_run_done`). All options are in `settings.json` (keys `font_px`, `target_lang`, `scope`, `enabled`, `proxy_mode`, `allowlist`, `first_run_done`), each validated on load with per-key fallback to defaults; hand-editing `proxy_mode` and `allowlist` is the only way to change them (no menu). The live allowlist replaces `config.ALLOWLIST` (kept only as a fallback).
- **Open:** P4 (conhost/OpenConsole, VS Code terminal, Claude Code fullscreen, Alt+Shift block selection, selecting while streaming, 150% scale, second monitor, elevated terminal).
- **429 handling (done, unit-tested with fake sessions; not yet exercised against the real endpoint):** HTTP 429/500/502/503/504 are retried up to 3 tries per click; a 429 switches to the other route (direct <-> system proxy) when one exists, 5xx stays on the same route; sleep 0.8 s / 2 s or the numeric `Retry-After` (capped at 5 s). Network errors still try each route once. Other HTTP errors (e.g. 403) fail at once. Retryable failures show a Retry button in the popup; every try is logged with `try=`, `via=direct|proxy` and `http=`. Worst case a click keeps the single translate thread busy for roughly 10-30 s.
- **Icon:** 40 px (logical, scaled by DPI), no auto-hide timer. Left click translates; right click dismisses it; a new Shift+drag replaces it. Clicking elsewhere closes the popup (not the icon).
- **Tray:** blue rounded icon with a white letter "A"; menu = Font size submenu + Quit only (the rest of the planned menu is P3). Tooltip and a start-up balloon say "hold Shift while dragging".
- **Font size:** tray submenu Small 13 / Medium 16 / Large 19 / Extra large 23 px (no larger size; default 16), saved to `%APPDATA%\ClaudeCliTranslate\settings.json` (`cct\settings.py`, `tests\test_settings.py`). Popup width and max height scale with the font; longer text scrolls inside the popup.
- **Logs:** `%APPDATA%\ClaudeCliTranslate\cct.log` (never contains selected or translated text, only length + short hash) and `cct-fault.log` (faulthandler).

## Goal
A Windows 11 background tray app that mimics the Chrome extension "Simple Translate" for terminals running Claude Code CLI. **Trigger rule (user requirement): the app acts ONLY when the user makes a Shift+drag selection in an allowlisted terminal window; plain drags, clicks, double- and triple-clicks are ignored.** After a Shift+drag a small translate icon appears next to the pointer; clicking it opens a floating dark popup with the translation (auto-detect source, default target Russian), like the reference screenshots 01.jpg (icon) and 02.jpg (popup). It never steals focus from the terminal, never sends keystrokes, and never touches the clipboard except for the explicit copy-translation button.
Decision: standalone app, NOT a Claude Code skill/hook/plugin - hooks and skills only see prompts/tool calls, never mouse selections in the terminal UI.

## Phase 0 results (measured on this machine; Windows Terminal 1.24.11911, PowerShell 7.6, Claude Code in a normal window, i.e. not fullscreen mode)
1. Windows Terminal's TermControl exposes UIA TextPattern. GetSelection on the focused element returns the selected text for Shift+drag inside the Claude Code tab (3 of 3) and for every selection kind in a plain PowerShell tab (9 of 9, drags up to 540 px across several rows, double-clicked words). The text is available already 50 ms after mouse-up and unchanged through 1500 ms, so retries/delays do not help; one read costs 3-35 ms.
2. UIA text comes back padded with trailing spaces on every terminal row (e.g. 973 characters returned for 116 real ones): per-line rstrip is mandatory.
3. In the Claude Code tab a PLAIN drag is handled by Claude Code itself: Windows Terminal has no selection (UIA empty 3 of 3) and Claude Code copies its own selection to the clipboard within 1.5 s (231/375/372 chars). Shift+drag bypasses Claude Code and creates a normal Windows Terminal selection with no auto-copy. This is exactly why Shift+drag is the trigger.
4. The synthetic Ctrl+Insert clipboard probe from the earlier plan is no longer needed and is REMOVED from the design (this also removes the clipboard-loss/privacy/race risks it carried; GLM's earlier HIGH-1 and MED-6 become moot).
5. comtypes 1.4.17 works on Python 3.14 when COM is set to MTA by `sys.coinit_flags = 0` BEFORE importing comtypes (calling CoInitializeEx afterwards fails with "Cannot change thread mode after it is set").
6. Not covered by the spike: conhost/OpenConsole, VS Code terminal, Claude Code fullscreen mode, elevated terminals. Verified only on Windows Terminal.

## Approach
Package `cct/` run via `pythonw -m cct` (plus `run.pyw`), PySide6 for UI + tray, ctypes/pywin32 for Win32.
1. **Phase 0 - DONE** (see results above).
2. **Trigger:** low-level mouse hook (WH_MOUSE_LL via ctypes) on a dedicated thread with its own message loop. The callback does ONLY: push (event, point, GetTickCount, Shift state sampled with GetAsyncKeyState(VK_SHIFT) at LBUTTONDOWN and again at LBUTTONUP, accepted if Shift was down at either, to tolerate GIL scheduling skew) into a SimpleQueue and return CallNextHookEx - no logging, no allocation-heavy work, no Qt calls (Windows silently unhooks callbacks slower than LowLevelHooksTimeout). A Qt-side consumer acts on LBUTTONUP only if ALL hold: Shift was held at button-down or button-up, drag distance >= 4 px, the foreground window's process exe is in the allowlist. Click chains (double/triple click) are not handled at all. Config `require_shift` (default true) exists for completeness; if false, plain drags in ordinary shells are accepted too (Claude Code plain drags still yield nothing because UIA is empty there). Events whose point lies inside cct's own windows are ignored. **Hook watchdog:** a Qt timer compares GetCursorPos movement with hook events; if the cursor moved for >N s with zero hook events it only sets a flag - the hook thread (which owns the message pump) performs the uninstall + reinstall itself and logs it (reinstalling from the GUI thread would make mouse callbacks dispatch on the GUI thread and stall it).
3. **Selection read = UIA only, zero keystrokes, zero clipboard access.** One replaceable UIA worker thread initialised as MTA (`sys.coinit_flags = 0` before importing comtypes), never called from the Qt GUI thread. It reads GetFocusedElement -> TextPattern.GetSelection -> GetText(-1) about 60 ms after mouse-up; if empty it retries once at about 250 ms; still empty -> no icon. ~500 ms watchdog per read; Python threads cannot be cancelled, so if the previous read is still running at the next request the worker is marked unhealthy, the strategy is skipped until that thread exits, and this is logged - never a pile of workers. Immediately before the UIA call the worker re-verifies that the foreground process is still allowlisted. All comtypes use stays on the worker thread, and the MTA import order (sys.coinit_flags) is re-verified inside the real PySide6 app in P2, because Qt's GUI thread initialises OLE/STA.
4. **Text normalisation** before display/translation: rstrip every line (UIA pads rows), drop trailing blank lines, strip Claude Code TUI decoration (leading box-drawing characters, bullet glyphs, prompt markers), join single hard line breaks produced by terminal wrapping into spaces while keeping blank-line paragraph breaks, BUT skip the join (keep newlines verbatim) when the text looks like code/table/block selection (block/Alt selection shape is unmeasured, verify in P4) (a line with a tab or 4+ leading spaces, code fences, box-drawing characters, or all lines of near-equal length); collapse runs of spaces; cap at 5000 chars (popup notes truncation).
5. **Icon window:** frameless 40x40 (logical px) QWidget showing "A文" on a blue rounded square, flags Qt.Tool | FramelessWindowHint | WindowStaysOnTopHint | WindowDoesNotAcceptFocus + WA_ShowWithoutActivating, and WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW via pywin32 so the terminal keeps focus. Shown at the mouse-up point +(10,10) clamped to the monitor work area immediately after a successful read (no click-chain delay is needed because click chains are ignored). All hit-testing, offsets and clamping are done in physical pixels; conversion to Qt logical coordinates happens in exactly one place at the Qt boundary (per-monitor DPI, PerMonitorV2, also at fractional 150%). No auto-hide timer: it stays until left-clicked (translate), right-clicked (dismiss) or replaced by the next Shift+drag.
6. **Popup window:** same non-activating flags; dark rounded panel (#1f1f1f bg, light text, user-selectable font 13/16/19/23 px (default 16), base width 360 px and base max height 260 px at 13 px, both scaled with the font; wrapped text, vertical scroll above the max height), small header with detected language -> target language, copy-translation button, close button. Placed under the selection point, clamped to the screen. Closes only on: close button, mouse-down outside it (seen via the global hook), or a new selection. No Esc handling (a non-activating window never receives keystrokes). Clicking the icon is handled by the icon widget itself and swallowed so it does not count as a new selection. The copy-translation button is the only clipboard write in the app and happens only on an explicit user click.
7. **Translation backend:** `Translator` interface with one provider for v1: the unofficial Google endpoint used by Simple Translate (https://translate.googleapis.com/translate_a/single?client=gtx&sl=auto&tl=<lang>&dt=t, POST for long text). requests.Session(trust_env=False) with explicit proxy control: config `proxy_mode` = `auto` (default: try direct; on connect error/timeout retry ONCE through the system SOCKS proxy read from urllib.request.getproxies(), via PySocks) | `direct` | `system`. 5 s connect / 10 s read timeout, worker thread, popup shows a spinner then text or a readable error. LRU cache (100). If detected source == target, show the translation with a small "same language" note. Nothing is sent on selection - only after the icon click. Retry on 429/5xx with route switching, a Retry button and per-try route logging are implemented (see Current status).
8. **Tray + config + logging** (P1/P2 shipped: tray icon with white "A", Font size submenu, Quit, settings.json for font size, rotating cct.log, cct-fault.log, excepthook; defaults currently live in `cct\config.py`; everything else below is P3): QSystemTrayIcon menu: Enable/Disable, Target language (ru default, en, de, uk, ...), Scope (terminals only / all apps), Start with Windows (HKCU\...\Run), Open log, Quit. A first-run notification and the tray tooltip tell the user: "Hold Shift while dragging to translate". Default allowlist: WindowsTerminal.exe only (verified); conhost.exe, OpenConsole.exe and Code.exe are added to the defaults only after P4 verification. Config JSON in %APPDATA%\ClaudeCliTranslate\settings.json (atomic write, defaults on corrupt file; keys: allowlist, target_lang, require_shift, proxy_mode). Single instance via named mutex. **Logging policy:** rotating log in %APPDATA%\ClaudeCliTranslate\cct.log; NEVER log raw selected or translated text (only length + short hash, and only in an opt-in verbose mode); one line per lookup with strategy, latency and status; `faulthandler.enable()` writing to the log file and a global sys.excepthook so pythonw crashes are not silent.
9. **Tests:** pytest for pure logic (normalisation incl. rstrip and code/table skip, Google response parsing, config load/save, physical-pixel geometry clamp, allowlist match, Shift/drag gating state machine). Manual matrix: Shift+drag in the Claude Code tab and a PowerShell tab of Windows Terminal; plain drag must do nothing; conhost, VS Code terminal and Claude Code fullscreen mode (unverified); 100%/150% DPI; two monitors; V2RayN on/off; clipboard holding an image (must stay untouched); Alt+Shift+drag block selection; a selection made while Claude Code is streaming output.
10. **Phases (P0-P3 DONE; P4 open):** P0 done -> P1 .gitignore (spike/ and all logs, before any push) + hook (Shift gating) + watchdog + icon (hard-coded text) -> P2 UIA read worker + translation + popup -> P3 tray/config/autostart/logging -> P4 hardening, verification of conhost/VS Code/fullscreen, test matrix.

## Key decisions & tradeoffs (please attack these)
1. Trigger = Shift+drag only (user requirement). It matches how Windows Terminal itself bypasses Claude Code's mouse handling, so UIA sees a real terminal selection; cost: users must remember Shift (mitigated by tooltip/first-run notice), no double-click/triple-click support.
2. UIA-only read with no clipboard access and no synthetic keystrokes (the probe and the clipboard-autocopy listener were both dropped; the autocopy listener would have supported plain drags but needs clipboard reads that can capture unrelated copies).
3. Global WH_MOUSE_LL hook with a watchdog restarted on the hook thread; cost: AV heuristics, must never block, UIPI blindness over elevated windows.
4. Python/PySide6 tray app vs AutoHotkey v2 vs C#/WPF: Python chosen, stack installed; cost: GIL, ~100 MB RAM.
5. Unofficial Google endpoint (no key) vs official Cloud Translation vs an LLM; privacy mitigated by sending text only after the icon click and never logging raw text.
6. Default allowlist = terminal hosts only; "all apps" is a tray toggle.
7. No Esc-to-close (focusless window).

## Risks / open questions
- Claude Code fullscreen mode, conhost/OpenConsole and VS Code terminal are unverified; Shift+drag is expected to bypass mouse reporting in all of them but this is not measured.
- A future Windows Terminal or Claude Code change to Shift+drag behaviour, or users rebinding it, would break the trigger.
- Terminal run as Administrator is invisible to a non-elevated hook (UIPI); documented limitation.
- Google gtx endpoint is unofficial: may rate-limit or change; no SLA. It has already returned HTTP 429 on two requests on one occasion; bounded retries now exist, but a persistent block still ends in a Retry-button error.
- Watchdog can false-positive on the secure desktop (UAC prompt): harmless spurious reinstall, log noise only.
- Text re-flow heuristics may still mangle unusual content; mitigation is the code/table skip rule.

## Out of scope
OCR / screenshot translation, macOS/Linux, keyboard-driven selection, plain-drag/double-click/triple-click triggers, reading Claude Code's auto-copied clipboard, clipboard probing, translation history UI, offline translation, installer/auto-update, TTS, dictionary mode, multiple providers (interface only).
